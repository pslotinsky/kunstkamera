# Debt Dungeon — Game Design Documentation

This documentation describes the **current target vision** for the game, rather than the state of a particular implementation.

1. [Vision](vision.md) — the experience we want to create.
2. [Systems overview](overview.md) — a map of game systems and their responsibilities.
3. [Systems](overview.md) — concepts for individual parts of the game.
4. [Game content](content/README.md) — preliminary labyrinth and creature archetypes.
5. [References](references.md) — main inspirations and confirmed areas of influence.

## Statuses

- **CONCEPT** — the system's purpose, boundaries, and main interactions are understood; specific rules remain open.
- **DRAFT** — rules are being designed and may contain unresolved questions.
- **SPEC** — rules are specific enough for implementation.

## Documentation Principles

- Each mechanic has one primary home. Other documents link to it rather than repeat its rules.
- The overview records purpose and connections, but does not replace detailed system descriptions.
- Documents describe the evolving target design. Change history belongs in Git.
- Undecided matters are explicitly identified; assumptions are not presented as confirmed rules.
- Intermediate implementations and iteration constraints are documented separately from the target game design.
